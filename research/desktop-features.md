# Hermes Desktop renderer: feature and behavior audit

Audited source: `upstream/hermes-agent`, commit `a566d20d226a8e2ef0747639dc8a3fc1c43f9dba`, desktop package version `0.17.6`, inspected September 17, 2026. References use verified line numbers. To keep tables readable, paths beginning `app/`, `store/`, `components/`, `lib/`, `api/`, `plugins/`, or `debug/` are relative to repository directory `apps/desktop/src/`; `e2e/` paths are relative to `apps/desktop/`. Other paths are repository-relative. This is a source audit, not a claim that the app or all tests were executed. Root, desktop, and renderer `AGENTS.md` were consulted. Electron shell/installer/transport and plugin ABI are covered by the other audits.

The important scope finding is that this is an agent workstation, not just a chat application. It includes multiple simultaneously live sessions across connections and profiles, arbitrary split/tab layouts, a development environment, fleet/bot collaboration, capability management, automation, and account administration. Replacing only the chat transcript and settings would leave a large fraction of the product missing.

## Chat, sessions, and the workspace

### Composer and submission

The composer is a rich editing surface, not a plain multiline string field. It owns file/folder/image/URL/terminal-selection attachments (`store/composer.ts:6-12`), per-session persisted drafts (`:175`), drag/drop, image clipboard paste, large-paste conversion, `@` file/folder/agent completions, slash/skill/quick-command completions, emoji completion, clickable path and URL chips, URL dialog, custom undo/redo/history, screenshot attachment, dictation, model/reasoning controls, and a draggable floating composer. The coordinator imports these separate engines at `app/chat/composer/index.tsx:34-99`.

The exact send state machine is part of parity: save an edited queued entry; run eligible slash commands while busy; queue; drain; send; stop; or steer the active turn (`app/chat/composer/hooks/use-composer-submit.ts:47`). Read final editor contents at dispatch, including IME completion, rather than trusting one-render-old state (`:192`). A rejected send restores the submitted draft to its **captured session scope**, even after the user switches chats (`:86-111`). Hidden machine notes never restore into the human draft. Attachments and slash commands cannot take the plain-text steering path (`store/composer-queue.ts:20`). Esc while parked on approval/secret/sudo/clarification does not discard the pending request (`composer/index.tsx:184-193`).

Queue editing, removal, reorder/send-now/drain are substantive features. Queues persist locally; explicitly halted queues are parked in memory (`store/composer-queue.ts:31-73`). Offscreen sessions have a separate queue-drain coordinator so they continue while another chat is selected (`app/session/hooks/use-background-queue-drain.ts:32-39,112-138`). This logic must not accidentally disappear when moving from React effects to native lifecycle.

Slash commands are curated for desktop discovery, but user skill and quick-command extensions remain executable. Dispatch can be client-owned, `slash.exec`, fallback `command.dispatch`, normal prompt expansion, or dedicated long-running RPCs such as compression (`app/session/hooks/use-prompt-actions/slash.ts:383,419,599,648`). Do not port only the visible built-in menu. Use the backend catalog and the existing desktop registry contract.

**Native mapping:** an AppKit `NSTextView` wrapper on macOS and UIKit text view on iOS is a stronger starting point than a basic SwiftUI `TextEditor`: attributed attachments/chips, selection, IME, undo, drop/paste, and input-method correctness are acceptance criteria. Keep draft/queue/submit state machines in shared Swift domain code; adapt keyboard gestures by platform.

### Transcript, live tools, and interaction

The transcript has user/assistant/system messages, streaming interim and final output, reasoning/thinking disclosure with timers, grouped tools, delegation cards, connector setup/execution, MCP setup, generated images, error/recovery cards, changed-files summaries, copy/retry/branch/edit/restore, message reactions/tapbacks, optional timestamps, read-aloud, and agent-to-agent delivery notices (`components/assistant-ui/thread/message-parts.tsx:12-32`; `assistant-message.tsx:16-64,93`; `user-message.tsx`; `user-edit-composer.tsx`). Reasoning keeps its measured duration and reader position; completed content does not suddenly unmount (`message-parts.tsx:161-195`).

Markdown includes tables, highlighted code, math, Mermaid, SVG/HTML artifacts and rich media/provider embeds (source registry: `components/assistant-ui/embeds/registry.tsx`; individual provider/iframe/consent components under that directory). Embed consent has ask/always/off semantics (`store/embed-consent.ts:4,18`). HTML/artifacts need deliberately contained WebKit islands even when shell/chat controls are native. Native text rendering alone does not reproduce these formats.

Long transcripts are bounded windows with older/newer paging, direct durable-row addressing, historical mode and return-to-latest (`components/assistant-ui/thread/transcript-window.tsx:5-19`). The UI pages DOM content before asking the server for more and preserves the user's top/bottom intent (`:47-98`). A native lazy list must preserve these properties under streamed insertions and variable-height rich content.

Tool approvals use an independent pending stack with choices once/session/always/deny, rather than attaching request ownership to the arrival of a tool row (`components/assistant-ui/tool/approval.tsx:44-72`). Clarification, credentials/sudo and connection requests are separately dispatched (`app/session/hooks/use-message-stream/gateway-event/input-requests.ts`). All may arrive or replay after reconnect; none may target the ambient wrong chat.

Status stack: todos, goals, background processes and subagents (`store/composer-status.ts:25,254`); subagent transcript/live state plus steer/interrupt routed to the child's owner (`app/chat/composer/status-stack/subagent-controls.tsx:21-39`); goal criteria/progress and resume kickoff, loop and heartbeat state/actions (`session-control.tsx:83-106`, `session-control-goal.tsx:73-111`, `session-control-loop.tsx:79-105`, `session-control-heartbeat.tsx:89-99`). A goal resume can return a hidden kickoff prompt, which must queue if already busy.

### Session organization

Sidebar/session actions include new chat, search, filters/groupings, paging/virtual rows, pinned/read/unread states, per-session colors, archive/delete, rename, branch, JSON export, new tab, split beside any pane, new native window, reopen/close tab groups, and local TUI handoff. `app/chat/sidebar/session-actions-menu.tsx:185-359` defines the main actions; tab close/reload semantics follow at `:362`; local terminal handoff is hidden for remote sessions at `:258`. `app/settings/sessions-settings.tsx:58` restores archived sessions, `:90` deletes them, and `:213` configures automatic archival.

`session.resume`/`session.activate` and cached provisional display are different transitions, not simply one fetch. First-send creation, existing live activation, history resume, fork/branch, and deletion/archive coordinate durable IDs, optimistic rows, runtime bindings and stale-response barriers (`app/session/hooks/use-session-actions/index.ts:563,788,1281,1706,2222,2727`). Edited/retried/restored messages use durable row IDs and rebind surviving row IDs after truncation (`app/session/hooks/use-prompt-actions/rewind.ts:38,90,160,211,257`), not fragile transcript indexes.

### Layout, projects, developer tools

The shell is an arbitrary layout tree of row/column splits and tab groups. Defaults cover sessions, workspace, review, files and terminal; dynamic previews are panes docked beside the file tree. Presets include default, focus, terminal-deck, quad, and a gated basic onboarding layout (`app/contrib/layout-presets.ts:9-73`). Sessions and other route pages can occupy independent tiles. Session tile persistence records stable session ID, exact owner route, workspace mode/owner, tab title, docking side/anchor/position; runtime IDs are deliberately not persisted (`store/session-states.ts:833-906`). Native implementation needs a real workspace controller; a single fixed `NavigationSplitView` is insufficient for full macOS parity.

Projects support explicit project records and automatically discovered repositories, multiple folders, active project selection, sidebar scope, appearance, move-session-to-project, repository/branch/worktree grouping, and worktree creation or existing-branch conversion with base branch picker (`app/chat/sidebar/projects/project-menu.tsx:40-122`; `worktree-dialog.tsx:55-67`; `store/projects.ts`). Removing an auto project is a sidebar dismissal; removing an explicit project removes its record, not source files.

File browser loads lazily with expanded-state retention, refresh/collapse, ignored-file display and file/folder activation. Critically it waits until the current CWD is owned by the selected session; a stale CWD during connection switch must not read the wrong machine (`app/right-sidebar/index.tsx:32-54`). File preview supports source/rendered/diff, Markdown, images, PDFs, edit/save with dirty/conflict state, and draggable line-range references into chat (`app/chat/right-rail/preview-file.tsx:419,529,541,662-695`). Text reads are bounded at 512 KiB and source lines windowed (`:44-47`). Artifacts support source/rendered modes and version stepping (`preview-artifact.tsx:110,175-198`).

Terminal is multi-tab, with xterm, fitting/serialization/Unicode/web-link support, live PTY events, selections to composer and buffer restoration (`app/right-sidebar/terminal/use-terminal-session.ts:449,495-575`). It remains alive when hidden; terminal visibility is not lifetime (`persistent.tsx`; `chrome.tsx:7-12`). A native terminal emulator spike is required; merely spawning a shell is insufficient.

Git review supports tree/list diff, per-file/all staging, unstaging, revert confirmation, virtualized syntax-highlighted diffs, direct commit/commit-and-push, model-generated commit message with cancel, PR open/create, and a user-triggered agent handoff to ship (`app/right-sidebar/review/index.tsx:46-225`; `ship-bar.tsx:32-35,57-76,111-155`). Keep file operations and Git ownership captured to the originating workspace throughout async calls.

In-app browser, browser automation/annotation/console, real-profile browser access and browser windows are separate major surfaces under `app/chat/right-rail/preview*.ts[x]`; the parent audit covers their detailed capability contract. Native WebKit cannot be assumed to be an Electron `<webview>` or Chromium DevTools Protocol drop-in.

## State authority and failure invariants to preserve

1. Backend owns sessions, model execution, settings another Hermes surface can edit, capabilities and scheduled work. Host layer owns OS/runtime facts. Presentation layer owns view state. This is the explicit desktop engineering contract (`apps/desktop/AGENTS.md:12`). Keep Swift UI models as caches rather than a second authoritative session database.
2. Identity is at least **connection + profile + stored session + runtime session + lineage root**. Profile name `default` is not globally unique. Event routing compares composite connection/profile scope (`app/session/hooks/use-message-stream/gateway-event/index.ts:137-146`). Use distinct Swift types, not interchangeable `String` parameters.
3. Persist only durable tab routes/placements; rebind runtimes after reconnect/reclaim. Reconnecting one connection cannot clear healthy tiles bound to another (`store/session-states.ts:1383-1420`).
4. Background streams update their own cache without changing foreground selection/focus. Per-session subscriptions avoid repainting the whole shell for each token (`store/session-states.ts:1-16`; `app/contrib/surfaces.tsx:1-7`). Coalesce cosmetic deltas; deliver attention/end/error immediately.
5. Connection/mode soft switch, process-home reload and live profile socket switch are distinct. Carry these semantics into a connection coordinator instead of rebuilding the entire app on every switch (`apps/desktop/AGENTS.md`, “Switching context is a re-home, not a reboot”).
6. Session activation/resume/create and stale asynchronous events require generation guards, exact owner provenance and finite recovery; transient transport failure is not deleted-session evidence. Pending approvals and input requests replay on reconnect.
7. Preserve durable submit semantics: first user message exists before slow agent initialization; force quit cannot erase it (documented desktop guide; backend audit traces persistence).
8. Rewind/retry/edit cannot truncate by naive visible index; hidden rows, compression and synthetic renderer IDs make that unsafe (`rewind.ts:160-257`).
9. Config editing seeds a draft once, diffs against its baseline, serializes writes and never overwrites untouched out-of-band CLI changes (`app/settings/config-settings.tsx:96-159,185-216`). Changing profile cancels/reseeds drafts; vault additionally clears transient secret fields.
10. Profile rename migrates tabs/navigation/owner hints/transcript tails, not just display text (`app/profiles/rename-profile-dialog.tsx:20-21`; `store/session-states.ts` migration functions). Bots canonical identity remains title-based.
11. Request-shaped data cache invalidation is not enough to clear live session stores after a connection apply. Concurrent owners and duplicated surface mounts must not create multiple approvals or dialogs.
12. Visibility is not lifetime: hidden terminal/preview/session surfaces retain relevant sessions; select/focus must not occur merely because a background job completes.
13. Local/remote filesystem routing is explicit. A path from a remote session is not an equivalent local path; preview, artifacts, Git, file dialogs and attachments need ownership-aware adapters.
14. Persisted queues are currently client-owned. On iOS, suspension would stop offscreen drain. Decide to move pending-intent orchestration to the backend with idempotency/acknowledgment, or explicitly expose queued-for-next-foreground semantics. Do not assume iOS background execution sustains the current React effect.
15. Bots cross-connection relay currently lives in renderer lifetime (`plugins/hermes-bots/plugin.tsx:104-115`). If iOS must preserve collaboration while backgrounded, its durable relay authority must be moved to an always-on host/service, including owner routing and deduplication. Porting a timer loop to Swift is insufficient.

- Release gates compare representative real transcripts, long streams, many open panes, large session sidebar, terminal floods and large diffs. Measure responsiveness/energy/memory on real Macs; an empty mock transcript is not adequate parity evidence.

Do not mechanically port hundreds of React DOM/layout snapshots. Reuse the behavior corpus, transport fixtures, adversarial ownership scenarios, and representative content; write native contract/UI tests for the changed implementation.

## Implementation sequencing implications

1. Build shared identity/protocol/store/reconciliation/draft/submit foundation first, and prove one local + one remote session before broad UI porting.
2. Deliver core native chat with durable history/streaming/approvals/attachments/branching, followed immediately by multi-session/profile ownership tests; leaving this until the end makes every feature unsafe.
3. Build native workspace panes/projects/files/Git/terminal with specialized editor/terminal/browser spikes in parallel. These are independent high-effort components, not a final polish phase.
4. Bring capabilities, settings, operations, automation, messaging, billing and learning UI across using existing backend endpoints. Preserve flags/deep links/profile scoping and compatibility behavior.
5. Port bundled Bots/Kanban/Radio deliberately. Their current React views do not become native through the plugin SDK. Define third-party desktop-plugin compatibility separately from full first-party feature parity.
6. Prove macOS lifecycle/windows/voice/system integrations and migration alongside these phases, then release only after the full surface matrix is checked against real runtime behavior.
7. Start the iOS client after the shared core is proven, but design its suspended/offline lifecycle, remote attachments, server queue/relay ownership and notification delivery now. On iPhone, navigation/sheets replace arbitrary desktop panes; execution/terminal/Git live on the remote host. This changes presentation and capability exposure, not Hermes core behavior.
